# Template migration object selector contract review

| Item | Contract |
| --- | --- |
| Owner | Published `tiwater-docx` template-migration observation capability. |
| Primary input | One current source DOCX and one selected baseline DOCX; both are inventoried independently. |
| Machine output | Each distinguishable pending source object carries a unique `Selector` and structural context. Repeated pending source objects that no published semantic selector can distinguish are returned once with their count and required all-cardinality resolution. Candidate discovery also returns the complete selectable baseline inventory as contextual `AvailableTargets` regions; selectable child runs remain attached to their unclaimed parent region. A region claimed by automatic mapping and its children are omitted because its parent operation already owns that content. Discovery returns neither an executable plan nor a target recommendation. |
| Invariants | A single selectable source or target observation contains kind, scope, visible text, a unique selector, and any available adjacent text, same-row text, and directly owned selectable runs. A repeated source group contains one selector that resolves exactly the stated count, and every selected object is pending; it can only use the resolver's existing all-cardinality terminal. Observations contain no object id, index, coordinate, scenario value, or inferred business mapping. Source context and the available target inventory are recomputed from the same hash-bound analysis; already mapped source children and target regions already owned by an automatic parent mapping are omitted. Reordering non-semantic package metadata does not change them. |
| Consumer | An Agent considers every required source, chooses source and baseline objects by business meaning, and copies published selectors into an existing semantic candidate. The Agent does not join technical object ids back to the full analysis inventory. The resolver independently reopens both current documents, resolves those selectors, and reports an omitted required source as a missing semantic decision rather than reusing a mechanical target-matching reason. |
| Compatibility | Discovery v5 removes v4's competing mechanical suggestion surface and groups source observations that had no valid selector; all distinguishable source and contextual target observations remain unchanged, and resolver input is unchanged. Runtime-pinned v2/v3/v4 callers retain their published package behavior. The legacy anchor-gap and exact-plan commands remain callable but are hidden from new discovery. The conditional review closer remains callable and is discoverable from semantic resolution rather than as a competing top-level route. Existing analysis, resolver, and semantic-candidate branches remain valid. |
| Non-goals | Choosing a source-to-target mapping, deciding a disposition, deriving business values, accepting object ids or coordinates in candidates, editing documents, or replacing independent resolution and readback. |
